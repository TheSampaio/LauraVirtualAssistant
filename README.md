# Laura Virtual Assistant

Laura is a Windows personal assistant built with **.NET 10 / .NET MAUI**, native WinUI controls and a dark red HUD. Concentric reactor rings rotate in opposite directions, pulse in the same red as idle while listening and glow bright red while speaking. CPU, RAM, GPU, dedicated VRAM, disk active time and Ethernet traffic have real progress meters. Network utilization is relative to the wired adapter's link capacity, not an Internet speed test.

The HUD uses a shared four-point spacing scale, quiet dark surfaces and bundled Lucide SVG icons. The monitor orders CPU, RAM, GPU, dedicated VRAM, every physical disk by its Windows number, and Ethernet. GPU usage and system-wide dedicated memory refer to the same hardware adapter; shared RAM is not presented as VRAM. Disk bars measure active time, with physical capacity and mapped drive letters underneath. Ethernet measures a connected wired adapter separately from the general network statistics provided to assistant tools. Unavailable readings hide their bar. Native metadata discovery and sampling run off the UI thread. Conversation bubbles identify the author and timestamp, with compact voice actions above the composer and translated tooltips. At widths below 1220, the header's monitor button switches the left panel between the reactor and scrollable system dashboard, keeping chat and input accessible down to 720 × 600. Reactor geometry is retained; Windows' animation preference disables continuous motion. Chat scrolls by coordinates after layout so history replacement cannot reference a detached bubble, and reading earlier messages does not force scrolling to the newest response.

## Install and start

Run `_Output/Distribution/LauraSetup.exe`, generated by `Build/Publish.bat`, or extract the complete `Laura-win-x64.zip` and run `Laura.exe`. The self-contained package includes .NET, Windows App SDK, audio/SQLite dependencies, required C++ runtimes and original license notices; keys and personal state are never bundled. `Verify-Package.ps1 -PackageDirectory <extracted-folder>` verifies the complete file manifest and pinned native dependencies. Windows x64, Windows 10 build 19041 or newer is supported. Android/iOS platform adapters are not implemented.

Normal launch stays hidden in the system tray, including first run. Press **Alt + L** to show or hide the HUD, then open settings to choose local inference or configure an optional text provider. Each reveal centers the normal window in its monitor's usable area, accounting for the taskbar. Only the close caption button remains; closing hides Laura in the tray. **F11** enters/leaves native fullscreen, restoring a centered close-only window on exit; tray reopening preserves an active fullscreen presenter. The native window is prepared in the background; navigation starts immediately with a lightweight 300 ms arrival transition, cached settings controls and respect for reduced motion. `--show` explicitly reveals the window for diagnostics. The monitor reserves a scrollbar gutter and wraps audio-device details. Reactor rings and pulses share a continuous 7200-degree cycle and advance by elapsed time, preserving phase across navigation.

Settings, SQLite memory, reminders and the assistant workspace live in **Documents/Laura Virtual Assistant**. Optional ChatGPT tokens belong to the separate LocalService credential broker in restricted ProgramData storage; see [service installation and boundaries](docs/CredentialBroker.md). Existing settings and memory are retained. Close Laura before updating. The installer is unsigned. Removing the per-user app does not remove or revoke the optional service account session.

See [current agent execution architecture](docs/architecture/laura-agent-execution.md) for provider migration, permissions, processes and diagnostics.

The [Laura 2.2 implementation report](LAURA-2.2-MIGRATION.md) records the current local-first architecture, measured validation and remaining physical evaluation limits.

## Ready-to-use local models and interface

Open Settings → Models and click **Install models and voice**. Laura configures
Qwen, llama.cpp, Whisper Base and Small, Kokoro, and female Portuguese/British Piper voices together and saves them automatically. Model
files stay directly in Documents/Laura Virtual Assistant/Models; runtime and support
files stay outside Models. Compatible GPUs are selected automatically through Vulkan;
machines without compatible GPUs use CPU. No separate Ollama installation is needed.

Settings uses a vertical navigation rail, with GPT in Connections and MCP last.
The reactor uses native MAUI rendering. See the [operation guide](docs/architecture/laura-local-first.md).

## Conversation and execution

Native C# skills run first. Automatic Light requests use the explicit choice in **Settings → Connections**: Gemini Live or the optional local model. New installations leave the local model disabled; choosing Gemini never loads Qwen. **Settings → Models** enables local inference when wanted. The AI Studio key is stored separately with Windows DPAPI. Gemini replies use native Live audio; local replies use the selected Kokoro/Piper voice. Standard and advanced requests can use authorized GPT; manual provider choices are preserved. ChatGPT uses official account authorization and eligible plan sharing, with no paid API-key fallback. Brain uses local FTS5 and graph retrieval without automatic cloud embedding uploads. No Claude connection is active; see the [future integration contract](docs/architecture/claude-future.md).

Security offers Ask for approval, Approve for me and Full access. Approve for me covers bounded task-linked code and file work inside Laura's assigned Workspace, verified GUI actions, literal installed-program version queries and structured anonymous public cloning into new directories there. Other effects require native approval. Full access requires a native warning confirmation and activation for the current process; its HUD badge and settings control show and revoke that state. Windows permissions, UAC, cancellation, execution limits and process-tree cleanup still apply. Arbitrary PowerShell, builds and dependency installation are not automatically approved in Approve for me because a working directory does not confine a process. See the [permission autonomy review](docs/architecture/permission-autonomy-2026-10-18.md) for the tested scope and remaining limits.

The structured run_powershell tool uses the same owned native executor as run_program and start_program. It supports the Windows inbox PowerShell host without requiring PowerShell 7, literal command text, task environment overrides, background jobs, stdout/stderr, exit codes, timeout and cancellation. New child processes refresh PATH from process, machine and user settings without changing the Windows PATH. Process tools preserve typed argument arrays and reject malformed supplied values. After a timeout, recent_task_context recovers owner-linked task objectives and freshly authorized repository cursors without replaying successful effects.

## Models and voice

Settings has a vertical rail: **Connections**, **Models**, **Voice**, **Preferences**, **Applications**, **Security** and **MCP**. Connections manages Gemini's AI Studio key, native voice and Light choice alongside the optional GPT account; Models manages Qwen, llama.cpp, Whisper, Kokoro and female Piper voices. Conversation and UI languages remain independent. Portuguese defaults to Dii (`pt_dii`), a Brazilian female voice licensed for non-commercial use with TigreGotico Lda attribution. Cori (`gb_cori`) is a British female English option. Kokoro's female voices remain available for local inference.

The one-click model installer verifies pinned sizes and SHA-256 hashes, resumes downloads and stages archive extraction. The default Models directory is beside Brain under Documents, with no subfolders inside Models. The separate Runtime directory contains llama.cpp and phonemizer support. A compatible GPU is selected automatically; CPU is used when a compatible GPU is unavailable. Missing voice assets leave the written answer available. ## Tasks and repository study

The HUD activity action opens private task progress, stop and explicit resume controls. Checkpoints are protected with Windows DPAPI outside the shared Brain; arguments and full tool output are not retained. A started effect without a confirmed result is never automatically replayed. Resume preserves cumulative progress and reacquires required permissions; a native user can request another bounded slice, up to 256 calls/one hour. Denials and uncertain external effects require inspection or a new explicit task.

Ask Laura to study an absolute local repository path or a public GitHub URL. The incremental coordinator preserves inventory, actual acquisition coverage and source references across batches/restarts. Local batches contain at most 64 files; remote batches at most 24, with separate byte/request limits. GitHub traversal follows immutable nonrecursive subtrees instead of treating a truncated recursive list as a complete project. The initial review is limited to that task, repository and actual disclosure recipient. It never authorizes code execution or project edits. Acquired source text remains untrusted; importing every eligible file does not prove full understanding or a passing build. See [architecture and measured limits](docs/architecture/laura-cognitive-evolution.md).

## Talk and control

Unmute with **M**. Hold **Ctrl + Space** to record only while those keys remain held; releasing ends the turn and closes the microphone. The hold shortcut works globally on Windows. Alternatively, **Start listening** enables continuous capture: Local endpoint detection recognizes a pause; Whisper transcribes it, the selected text engine replies and Kokoro speaks before capture resumes. The button stops the listening session, rather than ending each sentence. With default settings, capture never starts automatically on launch.

**Settings → Voice → Wake with claps** is an explicit opt-in, disabled by default. Wake requires installed local voice assets and an available selected text provider. With the microphone unmuted, the local stream detects two short claps spaced 180–900 ms apart. The sensitivity slider adapts the threshold to the room and microphone. Detection audio is neither stored nor transmitted. Capture pauses during conversation and playback; two claps close detection, speak a short varied acknowledgment (optionally using the owner's name), then start local continuous listening after playback drains. Explicit listening uses an exclusive handoff that keeps detection closed. Claps do not collect or repeat the daily briefing. The HUD distinguishes local clap detection from conversation listening. Muting or disabling the option closes detection; settings changes, Esc or standby cancel a pending wake. Conversation audio uses the selected local speech model.

With **Greet on startup** enabled, Laura opens once per process with a greeting and a concise spoken briefing. **Settings → Preferences → Weather city** accepts an optional city; when blank, wttr.in detects one from the public IP address. Laura distinguishes a recent observed condition from the forecast for the next hours, mentions useful rain or thunder risk and available daily temperature extremes, and omits unsupported conditions. It only calls an observation current when the provider's local timestamp is at most two hours old. Weather responses are cached for 20 minutes and refreshed across local midnight. Provider alerts are mentioned only when supplied; this is not a guaranteed official severe-weather alert service.

The same opening includes up to three recent BBC headlines with article dates/links, reminders due within 24 hours, and the latest Banco Central SGS series 1 USD/BRL sale reference when published within seven days. The quote keeps its original numeric value internally and is spoken as a dated reference formatted in Brazilian reais with two decimal places, never as a live spot price. Currency responses are cached for one hour. Weather and currency wording is prepared in C# without an additional model call. A fresh installation defers this opening until an enabled text provider is available. Startup remains hidden and does not open microphone capture. Missing sources are omitted instead of invented. Future email skills/plugins can implement `IBriefingContributor`. Source JSON bypasses local command recognition and is presented as data to the selected text provider; chat stores a concise startup title. Say **“that's all”**, **“stop listening”**, **“isso é tudo”** or **“pode descansar”** to close local capture, hear a short farewell and return to standby while leaving Laura running. The HUD includes a **Thinking** state with three phased pulsing dots and an orbiting light while sources or a model response are being prepared. Processing is silent; checkpoints do not emit automatic chat or voice announcements. Visual activity remains visible until the actual response arrives. Reduced motion keeps the processing markers static.

| Shortcut | Behavior |
| --- | --- |
| Ctrl + Space (hold) | Global push-to-talk; release closes capture |
| Esc | Interrupt generation, voice and capture |
| M | Mute/unmute; ignored while typing in a text field |
| F11 | Enter/leave native fullscreen |
| Alt + L | Show/hide Laura |

Esc, M and F11 apply while Laura has focus. Closing the window hides it in the tray; right-click the tray icon to exit. Continuous listening gates microphone packets during playback to reduce speaker echo. This does not implement acoustic echo cancellation or unrestricted full-duplex barge-in. Use Ctrl + Space or Esc to interrupt.

Whisper processes microphone PCM locally for local and GPT conversations. When Gemini Live is selected and listening is explicitly started, microphone audio goes to Gemini for native speech interaction. Typed/recognized text and approved requested context follow the selected text provider; Local mode uses only authenticated loopback inference. Written conversation history and bounded task context are independent of voice. Disabling conversation memory prevents saved history retrieval. Provider reset cancels old rounds and clears retained protocol context.

The output device starts with silence before model audio is accepted. A bounded PCM queue retains leading fragments during priming, flushes short completed turns, and waits for the hardware playback tail. Explicit interruption waits for the old native playback thread to stop before restarting; normal turn completion never clears pending speech. Automatic voice activity cannot interrupt Laura's outgoing response; explicit interruption remains available.

## Desktop capabilities

Every text provider receives the shared native tool contracts and calls the Windows adapters instead of guessing that it cannot act. Application discovery searches shortcuts, registry entries and portable application folders; it supports **Steam, PCSX2** and other actual installed programs rather than a fixed shortlist. Setup → Applications shows discovered names and targets.

Other tools provide real window selection, keyboard/mouse input, browser navigation/search/zoom, screen/webcam analysis, clipboard, volume/media/desktop controls, themes/wallpaper, file reading/editing/copy/move/reversible deletion, development program execution, memory search/editing and persistent reminders. Browser opening/search alone does not return page contents or verify current facts. Use actual native source results and authorized page inspection; offline inference cannot invent fresh news or rates. Protected effects use the independent **Approval Center**, accessible from the HUD shield and tray even when Laura is hidden/minimized. **Ask for Approval** is the default; **Automatic Approval** honors only explicit bounded local data policies. One-time/session/persistent grants, revocation, audit retention, visual notices and local Kokoro announcements are available in **Security**. Critical actions require reinforced UI confirmation; microphone audio cannot authorize them. Model file tools cannot edit security state, and application input cannot control Laura's own windows. Tool results report actual failures; the assistant must not invent success. See [permissions architecture and validation](docs/architecture/laura-permissions.md).

**LAURA Screenshot** is available from the HUD scan action and configurable global shortcuts in **Preferences** (PrtSc / Ctrl+PrtSc / Shift+PrtSc by default; conflicts are reported). It captures regions, selected windows with Windows Graphics Capture, or the virtual desktop, and opens an independent local editor with editable shapes, arrows, text, freehand/highlighter strokes, selection/removal and undo/redo. Copy uses the image clipboard; the Laura save form exports PNG/JPEG. **Analyze with LAURA** uses the existing visual conversation and requires a compatible authorized visual provider and explicit approval before sending exact pixels. **Save in Brain** attaches a deduplicated local asset to a real Markdown node; the reader and `read_brain_image` recover its pixels. Capture alone never uploads or saves a memory. Physical monitor/DPI and real mouse/hotkey acceptance checks remain documented limitations; see [Screenshot architecture](docs/architecture/laura-screenshot.md) and [delivery results](docs/architecture/laura-permissions-screenshot-delivery.md).

**Brain / Cérebro / LAURA Brain** stores durable knowledge as human-editable Markdown with versioned YAML, stable IDs, wikilinks and evidence-backed directed relations. It includes a native file tree, global/local interactive graph, reader, editor, split mode, metadata, reversible archival and conflict review. Existing SQLite facts are copied once without deleting their source; raw chat history remains separate. FTS5 indices are rebuildable installation caches outside the shared folder. Local text and graph retrieval preserve knowledge without model inference. Conservative automatic learning handles explicit preferences, projects, goals, decisions and procedures, deduplicates repeated declarations and preserves ambiguous corrections for review. Explicit owner-overview questions retrieve existing knowledge even without literal keyword overlap.

**Brain → Manage Brain** selects, creates or migrates a vault, verifies files, rebuilds indices, exports/restores private backups. A desktop synchronized folder can be selected; mobile document-provider adapters are not implemented. Markdown skills import disabled and require review. Text providers discover their real names/descriptions through `list_brain_skills` and loads guidance through `read_brain_skill`, matching task meaning across languages. A disabled or changed skill offers native review of its exact contents in the conversation; it is not reported as a missing ability. Approved text guidance is separate from factual memories and never installs dependencies or executes scripts. Plain notes/caches/backups are private readable data, not encrypted by this feature. Vault writes inside repositories receive exact Git protection. See [Brain architecture, formats, recovery and limits](docs/architecture/laura-brain.md). Run `Build/Verify-BrainPrivacy.ps1` before sharing source; include custom repository vaults with `-BrainDirectories`.

Retrieval adapts to the interaction: a closed set of greetings/time/date messages skips Brain work, while other requests use coherent snapshots and bounded context. Literal installation declarations (including explicit corrections) become inert application knowledge. Opening a learned application resolves a unique executable, revalidates its identity and requires the original native launch authorization; missing, conflicting or changed knowledge does not trigger speculative fallback. Typed input and completed voice transcripts share durable learning, and partial speech preserves the current turn identity. Brain writes publish changed documents and reuse unaffected index/graph state; visual refreshes are coalesced, and body edits keep graph positions. Playback preserves full 16-bit PCM samples across fragment boundaries, validates the native output format and reports observed gaps. See [audit, measured improvements, A/B audio diagnostics and remaining limits](docs/architecture/laura-brain-audio-stability.md).

Screenshot defaults use **Ctrl+Shift+F8** (region), **Ctrl+Shift+F9** (window) and **Ctrl+Shift+F10** (screen), leaving PrtSc to Windows. The original three default PrtSc chords migrate together; customized chords are preserved. Preferences offers recommended shortcuts and reports actual registration conflicts without replacing another app's registration.

The chat's **⋯** menu opens Activity logs with live metadata, filters, event copying and diagnostic export, and clears the real conversation session with confirmation, exports the complete retained dialogue to Markdown/TXT/JSON, and exports a **technical diagnostic ZIP** for manual sharing with ChatGPT. Conversation reset preserves Brain knowledge and permissions and fences late responses; already started external effects are not undone. Native selection/copy and multiline paste preserve text; Enter sends and Shift+Enter adds a line. Streaming/layout changes follow the newest message until you scroll upward; the down button resumes following.

Technical logs are local metadata in `%LOCALAPPDATA%/Laura/Diagnostics` (up to eight 1 MiB segments, at most seven days). They include timings, outcomes, configuration modes, audio gaps and resource counters without prompts, responses, screenshots, audio, paths, credential values or exception messages. The exported ZIP contains `report.md`, `summary.json` and `events.jsonl`, with explicit loss/failure counters. Export the conversation separately when its content is needed for behavior analysis and review personal data before sharing. Nothing uploads automatically. See [OpenClaw/OpenJarvis audit, chat/session architecture, diagnostics and validation](docs/architecture/laura-chat-diagnostics.md).

Reminders persist locally and speak through the selected local voice while Laura runs; overdue reminders resume on a subsequent launch. They are not OS tasks that wake a closed app. The Python plugin loader, mobile dashboard, proactive news monitoring and embedded video player from Mark-LV are not yet implemented. No reference source or assets are bundled.

## Build and verification

Development requires the SDK pinned in `global.json`, the Windows MAUI workload and Windows SDK. NuGet dependencies are locked and analyzer warnings are errors.

Version control includes source, tests, build scripts, dependency lock files, authored icons, documentation and upstream license notices. `.gitignore` excludes generated binaries/installers, `_Output` diagnostics, `graphify-out` analysis output, test/coverage artifacts, local tooling state, downloaded model weights, API keys, signing keys and personal settings, Brain caches, memory and reminders. Keep private Brain vaults, screenshots and credential files outside this repository; adding an ignore rule does not remove a file already tracked by Git. Run `Build/Verify-BrainPrivacy.ps1` before sharing source and publish release packages separately.

```powershell
dotnet restore Laura.sln --locked-mode
dotnet build Laura.sln -c Release --no-restore
dotnet test Laura.sln -c Release --no-restore
Build/Publish.bat
Build/Run.bat
```

Publishing requires a licensed Visual Studio release redistributable folder with the exact CRT hashes in `licenses/vc-runtime-inventory.json`. The default is Visual Studio 2026 Community `VC/Redist/MSVC/14.51.36231/x64`. `Build/Test-Package.ps1` verifies installer extraction, installation/update, packaged dependencies, removal of old integrations and tamper refusal.

Opt-in diagnostics use isolated storage and never capture a physical microphone:

```powershell

# Verify hidden startup, native toggle, scroll, reactor continuity and silent output restarts.
Laura.App/bin/Release/net10.0-windows10.0.19041.0/win-x64/Laura.exe --storage _Output/ReliabilitySmoke/Storage --ui-smoke _Output/ReliabilitySmoke --verify-background-startup

Laura.App/bin/Release/net10.0-windows10.0.19041.0/win-x64/Laura.exe --show --storage _Output/Laura22UI/Storage --ui-smoke _Output/Laura22UI --chatgpt-ui-smoke

# Explicit optional download, then real Qwen/tools/Kokoro/Whisper acceptance in EN/PT.

```

The offline pipeline uses synthetic text/audio, cloud providers disabled and no microphone. Keep all credentials and private data outside diagnostics and source control.
