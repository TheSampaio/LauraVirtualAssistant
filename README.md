# Laura Virtual Assistant

Laura is a Windows personal assistant built with **.NET 10 / .NET MAUI**, native WinUI controls and a dark red HUD. Concentric reactor rings rotate in opposite directions, pulse in the same red as idle while listening and glow bright red while speaking. CPU, RAM, GPU, dedicated VRAM, disk active time and Ethernet traffic have real progress meters. Network utilization is relative to the wired adapter's link capacity, not an Internet speed test.

The HUD uses a shared four-point spacing scale, quiet dark surfaces and bundled Lucide SVG icons. The monitor orders CPU, RAM, GPU, dedicated VRAM, every physical disk by its Windows number, and Ethernet. GPU usage and system-wide dedicated memory refer to the same hardware adapter; shared RAM is not presented as VRAM. Disk bars measure active time, with physical capacity and mapped drive letters underneath. Ethernet measures a connected wired adapter separately from the general network statistics provided to assistant tools. Unavailable readings hide their bar. Native metadata discovery and sampling run off the UI thread. Conversation bubbles identify the author and timestamp, with compact voice actions above the composer and translated tooltips. At widths below 1220, the header's monitor button switches the left panel between the reactor and scrollable system dashboard, keeping chat and input accessible down to 720 × 600. Reactor geometry is retained; Windows' animation preference disables continuous motion. Chat scrolls by coordinates after layout so history replacement cannot reference a detached bubble, and reading earlier messages does not force scrolling to the newest response.

## Install and start

Run `_Output/Distribution/LauraSetup.exe`, generated by `Build/Publish.bat`, or extract the complete `Laura-win-x64.zip` and run `Laura.exe`. The self-contained package includes .NET, Windows App SDK, audio/SQLite dependencies, required C++ runtimes and original license notices; keys and personal state are never bundled. `Verify-Package.ps1 -PackageDirectory <extracted-folder>` verifies the complete file manifest and pinned native dependencies. Windows x64, Windows 10 build 19041 or newer is supported. Android/iOS platform adapters are not implemented.

Normal launch stays hidden in the system tray, including first run. Press **Alt + L** to show or hide the HUD, then open settings to configure the protected key. Each reveal centers the normal window in its monitor's usable area, accounting for the taskbar. Only the close caption button remains; closing hides Laura in the tray. **F11** enters/leaves native fullscreen, restoring a centered close-only window on exit; tray reopening preserves an active fullscreen presenter. The native window is prepared in the background; navigation starts immediately with a lightweight 300 ms arrival transition, cached settings controls and respect for reduced motion. `--show` explicitly reveals the window for diagnostics. The monitor reserves a scrollbar gutter and wraps audio-device details. Reactor rings and pulses share a continuous 7200-degree cycle and advance by elapsed time, preserving phase across navigation.

Settings, encrypted credentials, SQLite memory, reminders and the assistant workspace live in **Documents/Laura Virtual Assistant**. Existing settings and memory are retained. Close Laura before updating. The installer is unsigned. To uninstall, disable Start with Windows, exit through the tray menu, and remove the installation/shortcut; personal data remains until explicitly removed.

See [current agent execution architecture](docs/architecture/laura-agent-execution.md) for provider migration, permissions, processes and diagnostics.

## Conversation and execution

Gemini Live is the sole conversation and voice provider. Enable it explicitly and configure a protected Google AI Studio key. Old Local, Auto and OpenAI settings migrate to Gemini with cloud conversation disabled until explicitly enabled. Former model downloads can be removed with the dedicated, confirmed cleanup action; unknown or shared files are preserved. Brain uses local FTS5 text search and graph retrieval without model inference or automatic cloud embedding uploads.

Security offers Ask for approval, Approve for me and Full access. Full access requires a native warning confirmation and a separate protected preference. Windows permissions, UAC, cancellation, execution limits and process-tree cleanup still apply. The automatic policy covers bounded workspace actions, verified GUI actions and literal installed-program version queries and structured anonymous public cloning into new directories in the assigned workspace; other effects require native approval.

The structured run_powershell tool uses the same owned native executor as run_program and start_program. It supports the Windows inbox PowerShell host without requiring PowerShell 7, literal command text, task environment overrides, background jobs, stdout/stderr, exit codes, timeout and cancellation. New child processes refresh PATH from process, machine and user settings without changing the Windows PATH. Process tools preserve typed argument arrays and reject malformed supplied values. After a timeout, recent_task_context recovers owner-linked task objectives and freshly authorized repository cursors without replaying successful effects.

## Google AI Studio

Google AI Studio / Gemini Live is the default conversation and voice provider. Open the **gear button → Connection**, enable Gemini, paste your key and save. New keys are validated through Live setup before saving; a fixed bullet mask indicates the protected saved key without exposing it. Laura stores its copy encrypted with Windows DPAPI for the current Windows account; keys do not enter INI files, logs or release packages.


Laura independently implements the same reviewed Live model identifiers and five native voices as the local reference: `gemini-3.1-flash-live-preview`, fallback `gemini-2.5-flash-native-audio-preview-12-2025`, and **Charon, Puck, Kore, Fenrir, Aoede**. Availability and quotas depend on the Google account. Conversation and speech use Gemini Live exclusively.

Setup has six tabs: **Connection**, **Voice**, **Preferences**, **Applications**, **Security**, **MCP**, with a fixed Save button. Security preferences can be saved without a cloud key. Voice includes native Gemini voice preview, microphone/output devices, volume and the silence interval used for automatic speech-end detection. Conversation and UI language are independently configurable; **Português (Brasil)** explicitly instructs the model to use Brazilian pronunciation and vocabulary.

## Tasks and repository study

The HUD activity action opens private task progress, stop and explicit resume controls. Checkpoints are protected with Windows DPAPI outside the shared Brain; arguments and full tool output are not retained. A started effect without a confirmed result is never automatically replayed. Resume preserves cumulative progress and reacquires required permissions; a native user can request another bounded slice, up to 256 calls/one hour. Denials and uncertain external effects require inspection or a new explicit task.

Ask Laura to study an absolute local repository path or a public GitHub URL. The incremental coordinator preserves inventory, actual acquisition coverage and source references across batches/restarts. Local batches contain at most 64 files; remote batches at most 24, with separate byte/request limits. GitHub traversal follows immutable nonrecursive subtrees instead of treating a truncated recursive list as a complete project. The initial review is limited to that task, repository and actual disclosure recipient. It never authorizes code execution or project edits. Acquired source text remains untrusted; importing every eligible file does not prove full understanding or a passing build. See [architecture and measured limits](docs/architecture/laura-cognitive-evolution.md).

## Talk and control

Unmute with **M**. Hold **Ctrl + Space** to record only while those keys remain held; releasing ends the turn and closes the microphone. The hold shortcut works globally on Windows. Alternatively, **Start listening** enables continuous capture: Gemini recognizes a pause and replies automatically, then waits for the next turn. The button stops the listening session, rather than ending each sentence. With default settings, capture never starts automatically on launch.

**Settings → Voice → Wake with claps** is an explicit opt-in, disabled by default. Gemini requires its explicitly enabled configuration and protected key. With the microphone unmuted, the local stream detects two short claps spaced 180–900 ms apart. The sensitivity slider adapts the threshold to the room and microphone. Detection audio is neither stored nor transmitted. Capture pauses during conversation and playback; two claps close detection, speak a short varied acknowledgment (optionally using the owner's name), then start Gemini continuous listening after playback drains. Explicit listening uses an exclusive handoff that keeps detection closed. Claps do not collect or repeat the daily briefing. The HUD distinguishes local clap detection from conversation listening. Muting or disabling the option closes detection; settings changes, Esc or standby cancel a pending wake. Conversation audio follows the explicit Gemini configuration.

With **Greet on startup** enabled, Laura opens once per process with a greeting and a concise spoken briefing: today's forecast minimum and maximum temperatures for the city detected by wttr.in from the public IP address, recent BBC headlines with article dates/links, the latest Banco Central SGS series 1 USD/BRL reference with its actual quotation date (not a live spot price), and reminders due within 24 hours. A fresh installation defers this opening until Gemini is configured. Startup remains hidden and does not open cloud microphone capture. An unavailable source is reported without invented values or email messages. Future email skills/plugins can implement `IBriefingContributor`. Source JSON bypasses local command recognition and is presented as data to Gemini; chat stores a concise startup title. Say **“that's all”**, **“stop listening”**, **“isso é tudo”** or **“pode descansar”** to close cloud capture, hear a short farewell and return to standby while leaving Laura running. The HUD includes a **Thinking** state with three phased pulsing dots and an orbiting light while sources or a model response are being prepared. Processing is silent: Gemini does not emit an automatic waiting announcement. Visual activity remains visible until the actual response arrives. Reduced motion keeps the processing markers static.

| Shortcut | Behavior |
| --- | --- |
| Ctrl + Space (hold) | Global push-to-talk; release closes capture |
| Esc | Interrupt generation, voice and capture |
| M | Mute/unmute; ignored while typing in a text field |
| F11 | Enter/leave native fullscreen |
| Alt + L | Show/hide Laura |

Esc, M and F11 apply while Laura has focus. Closing the window hides it in the tray; right-click the tray icon to exit. Continuous listening gates microphone packets during playback to reduce speaker echo. This does not implement acoustic echo cancellation or unrestricted full-duplex barge-in. Use Ctrl + Space or Esc to interrupt.

Typed prompts and explicitly captured audio go to Google. Input/output transcripts appear in chat, and native audio plays as it arrives. Persistent WebSocket sessions, compression/resumption and bounded saved history preserve conversation context. Disabling conversation memory also prevents saved history from entering new sessions. Current cloud session context remains until disconnect.

The output device starts with silence before model audio is accepted. A bounded PCM queue retains leading fragments during priming, flushes short completed turns, and waits for the hardware playback tail. Explicit interruption waits for the old native playback thread to stop before restarting; normal turn completion never clears pending speech. Automatic voice activity cannot interrupt Laura's outgoing response; explicit interruption remains available.

## Desktop capabilities

Gemini receives explicit tools and calls the Windows adapters instead of guessing that it cannot act. Application discovery searches shortcuts, registry entries and portable application folders; it supports **Steam, PCSX2** and other actual installed programs rather than a fixed shortlist. Setup → Applications shows discovered names and targets.

Other tools provide real window selection, keyboard/mouse input, browser navigation/search/zoom, screen/webcam analysis, clipboard, volume/media/desktop controls, themes/wallpaper, file reading/editing/copy/move/reversible deletion, development program execution, memory search/editing and persistent reminders. Google Search grounding supplies current web information. Protected effects use the independent **Approval Center**, accessible from the HUD shield and tray even when Laura is hidden/minimized. **Ask for Approval** is the default; **Automatic Approval** honors only explicit bounded local data policies. One-time/session/persistent grants, revocation, audit retention, visual notices and Gemini voice announcements are available in **Security**. Critical actions require reinforced UI confirmation; microphone audio cannot authorize them. Model file tools cannot edit security state, and application input cannot control Laura's own windows. Tool results report actual failures; the assistant must not invent success. See [permissions architecture and validation](docs/architecture/laura-permissions.md).

**LAURA Screenshot** is available from the HUD scan action and configurable global shortcuts in **Preferences** (PrtSc / Ctrl+PrtSc / Shift+PrtSc by default; conflicts are reported). It captures regions, selected windows with Windows Graphics Capture, or the virtual desktop, and opens an independent local editor with editable shapes, arrows, text, freehand/highlighter strokes, selection/removal and undo/redo. Copy uses the image clipboard; the Laura save form exports PNG/JPEG. **Analyze with LAURA** uses the existing visual conversation and requires explicit approval before sending exact pixels to Gemini. **Save in Brain** attaches a deduplicated local asset to a real Markdown node; the reader and `read_brain_image` recover its pixels. Capture alone never uploads or saves a memory. Physical monitor/DPI and real mouse/hotkey acceptance checks remain documented limitations; see [Screenshot architecture](docs/architecture/laura-screenshot.md) and [delivery results](docs/architecture/laura-permissions-screenshot-delivery.md).

**Brain / Cérebro / LAURA Brain** stores durable knowledge as human-editable Markdown with versioned YAML, stable IDs, wikilinks and evidence-backed directed relations. It includes a native file tree, global/local interactive graph, reader, editor, split mode, metadata, reversible archival and conflict review. Existing SQLite facts are copied once without deleting their source; raw chat history remains separate. FTS5 indices are rebuildable installation caches outside the shared folder. Local text and graph retrieval preserve knowledge without model inference. Conservative automatic learning handles explicit preferences, projects, goals, decisions and procedures, deduplicates repeated declarations and preserves ambiguous corrections for review. Explicit owner-overview questions retrieve existing knowledge even without literal keyword overlap.

**Brain → Manage Brain** selects, creates or migrates a vault, verifies files, rebuilds indices, exports/restores private backups. A desktop synchronized folder can be selected; mobile document-provider adapters are not implemented. Markdown skills import disabled and require review. Gemini discovers their real names/descriptions through `list_brain_skills` and loads guidance through `read_brain_skill`, matching task meaning across languages. A disabled or changed skill offers native review of its exact contents in the conversation; it is not reported as a missing ability. Approved text guidance is separate from factual memories and never installs dependencies or executes scripts. Plain notes/caches/backups are private readable data, not encrypted by this feature. Vault writes inside repositories receive exact Git protection. See [Brain architecture, formats, recovery and limits](docs/architecture/laura-brain.md). Run `Build/Verify-BrainPrivacy.ps1` before sharing source; include custom repository vaults with `-BrainDirectories`.

Retrieval adapts to the interaction: a closed set of greetings/time/date messages skips Brain work, while other requests use coherent snapshots and bounded context. Literal installation declarations (including explicit corrections) become inert application knowledge. Opening a learned application resolves a unique executable, revalidates its identity and requires the original native launch authorization; missing, conflicting or changed knowledge does not trigger speculative fallback. Typed input and completed voice transcripts share durable learning, and partial speech preserves the current turn identity. Brain writes publish changed documents and reuse unaffected index/graph state; visual refreshes are coalesced, and body edits keep graph positions. Playback preserves full 16-bit PCM samples across fragment boundaries, validates the native output format and reports observed gaps. See [audit, measured improvements, A/B audio diagnostics and remaining limits](docs/architecture/laura-brain-audio-stability.md).

Screenshot defaults use **Ctrl+Shift+F8** (region), **Ctrl+Shift+F9** (window) and **Ctrl+Shift+F10** (screen), leaving PrtSc to Windows. The original three default PrtSc chords migrate together; customized chords are preserved. Preferences offers recommended shortcuts and reports actual registration conflicts without replacing another app's registration.

The chat's **⋯** menu opens Activity logs with live metadata, filters, event copying and diagnostic export, and clears the real conversation session with confirmation, exports the complete retained dialogue to Markdown/TXT/JSON, and exports a **technical diagnostic ZIP** for manual sharing with ChatGPT. Conversation reset preserves Brain knowledge and permissions and fences late responses; already started external effects are not undone. Native selection/copy and multiline paste preserve text; Enter sends and Shift+Enter adds a line. Streaming/layout changes follow the newest message until you scroll upward; the down button resumes following.

Technical logs are local metadata in `%LOCALAPPDATA%/Laura/Diagnostics` (up to eight 1 MiB segments, at most seven days). They include timings, outcomes, configuration modes, audio gaps and resource counters without prompts, responses, screenshots, audio, paths, credential values or exception messages. The exported ZIP contains `report.md`, `summary.json` and `events.jsonl`, with explicit loss/failure counters. Export the conversation separately when its content is needed for behavior analysis and review personal data before sharing. Nothing uploads automatically. See [OpenClaw/OpenJarvis audit, chat/session architecture, diagnostics and validation](docs/architecture/laura-chat-diagnostics.md).

Reminders persist locally and speak through Gemini while Laura runs; overdue reminders resume on a subsequent launch. They are not OS tasks that wake a closed app. See `docs/architecture/maui-gemini-delivery.md` for the reference capability comparison and limits. The Python plugin loader, mobile dashboard, proactive news monitoring and embedded video player from Mark-LV are not yet implemented. No reference source or assets are bundled.

## Build and verification

Development requires the SDK pinned in `global.json`, the Windows MAUI workload and Windows SDK. NuGet dependencies are locked and analyzer warnings are errors.

Version control includes source, tests, build scripts, dependency lock files, authored icons, documentation and upstream license notices. Generated binaries/installers, `_Output` diagnostics, downloaded model weights, API keys, signing keys and personal settings/memory/reminders are excluded by `.gitignore`. Publish release packages separately from the source repository.

```powershell
dotnet restore Laura.sln --locked-mode
dotnet build Laura.sln -c Release --no-restore
dotnet test Laura.sln -c Release --no-restore
Build/Publish.bat
Build/Run.bat
```

Publishing requires a licensed Visual Studio release redistributable folder with the exact CRT hashes in `licenses/vc-runtime-inventory.json`. The default is Visual Studio 2026 Community `VC/Redist/MSVC/14.51.36231/x64`. `Build/Test-Package.ps1` verifies installer extraction, installation/update, packaged dependencies, removal of old integrations and tamper refusal.

Opt-in diagnostics use isolated storage and never capture a physical microphone:

# Verify hidden startup, native toggle, scroll, reactor continuity and silent output restarts.
Laura.App/bin/Release/net10.0-windows10.0.19041.0/win-x64/Laura.exe --storage _Output/ReliabilitySmoke/Storage --ui-smoke _Output/ReliabilitySmoke --verify-background-startup
