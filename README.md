# Laura Virtual Assistant

Laura is a Windows personal assistant built with **.NET 10 / .NET MAUI**, native WinUI controls and a dark red HUD. Concentric reactor rings rotate in opposite directions, pulse in the same red as idle while listening and glow bright red while speaking. CPU, memory, disk occupancy, current network traffic and GPU utilization have real progress meters. Network utilization is relative to the active adapter's link capacity, not an Internet speed test.

## Install and start

Run `_Output/Distribution/LauraSetup.exe`, generated by `Build/Publish.bat`, or extract the complete `Laura-win-x64.zip` and run `Laura.exe`. The self-contained package includes .NET, Windows App SDK, audio/SQLite dependencies, app-local C++ runtime and license notices. Windows x64, Windows 10 build 19041 or newer is supported. Android/iOS platform adapters are not implemented.

Settings, encrypted credentials, SQLite memory, reminders and the assistant workspace live in **Documents/Laura Virtual Assistant**. Existing settings and memory are retained. Close Laura before updating. The installer is unsigned. To uninstall, disable Start with Windows, exit through the tray menu, and remove the installation/shortcut; personal data remains until explicitly removed.

## Google AI Studio

Google AI Studio / Gemini Live is the sole conversation and voice provider. Open the **gear button → Connection**, paste your key or select **Import key and voice from Mark-LV**, then save. New keys are validated through Live setup before saving; a fixed bullet mask indicates the protected saved key without exposing it. Import reads `config/api_keys.json` without modifying the reference project. Laura stores its copy encrypted with Windows DPAPI for the current Windows account; keys do not enter INI files, logs or release packages.

Laura independently implements the same Live model identifiers and five native voices as the local reference: `gemini-3.1-flash-live-preview`, fallback `gemini-2.5-flash-native-audio-preview-12-2025`, and **Charon, Puck, Kore, Fenrir, Aoede**. Availability and quotas depend on the Google account. Windows/SAPI voices, Ollama, embedded llama inference and offline recognition/synthesis are removed from the application and its dependency graph.

Setup has four tabs: **Connection**, **Voice**, **Preferences**, **Applications**, with a fixed Save button. Voice includes native Gemini voice preview, microphone/output devices, volume and the silence interval used for automatic speech-end detection. Conversation and UI language are independently configurable; **Português (Brasil)** explicitly instructs the model to use Brazilian pronunciation and vocabulary.

## Talk and control

Unmute with **M**. Hold **Ctrl + Space** to record only while those keys remain held; releasing ends the turn and closes the microphone. The hold shortcut works globally on Windows. Alternatively, **Start listening** enables continuous capture: Gemini recognizes a pause and replies automatically, then waits for the next turn. The button stops the listening session, rather than ending each sentence. Capture never starts automatically on launch.

| Shortcut | Behavior |
| --- | --- |
| Ctrl + Space (hold) | Global push-to-talk; release closes capture |
| Esc | Interrupt generation, voice and capture |
| M | Mute/unmute; ignored while typing in a text field |
| F11 | Enter/leave native fullscreen |
| Alt + L | Show/hide Laura |

Esc, M and F11 apply while Laura has focus. Closing the window hides it in the tray; right-click the tray icon to exit. Continuous listening gates microphone packets during playback to reduce speaker echo. This does not implement acoustic echo cancellation or unrestricted full-duplex barge-in. Use Ctrl + Space or Esc to interrupt.

Typed prompts and explicitly captured audio go to Google. Input/output transcripts appear in chat, and native audio plays as it arrives. Persistent WebSocket sessions, compression/resumption and bounded saved history preserve conversation context. Disabling conversation memory also prevents saved history from entering new sessions. Current cloud session context remains until disconnect.

## Desktop capabilities

Gemini receives explicit tools and calls the Windows adapters instead of guessing that it cannot act. Application discovery searches shortcuts, registry entries and portable application folders; it supports **Steam, PCSX2** and other actual installed programs rather than a fixed shortlist. Setup → Applications shows discovered names and targets.

Other tools provide real window selection, keyboard/mouse input, browser navigation/search/zoom, screen/webcam analysis, clipboard, volume/media/desktop controls, themes/wallpaper, file reading/editing/copy/move/reversible deletion, development program execution, memory search/editing and persistent reminders. Google Search grounding supplies current web information. File changes, private capture/reading, executable invocations and consequential actions use a native confirmation dialog showing the concrete action. Tool results report actual failures; the assistant must not invent success.

**Memory** manages saved facts and conversation history. Reminders persist locally and speak through Gemini while Laura runs; overdue reminders resume on a subsequent launch. They are not OS tasks that wake a closed app. See `docs/architecture/maui-gemini-delivery.md` for the reference capability comparison and limits. The Python plugin loader, mobile dashboard, proactive news monitoring and embedded video player from Mark-LV are not yet implemented. No reference source or assets are bundled.

## Build and verification

Development requires the SDK pinned in `global.json`, the Windows MAUI workload and Windows SDK. NuGet dependencies are locked and analyzer warnings are errors.

Version control includes source, tests, build scripts, dependency lock files, authored icons, documentation and upstream license notices. Generated binaries/installers, `_Output` diagnostics, downloaded model weights, API keys, signing keys and personal settings/memory/reminders are excluded by `.gitignore`. Publish release packages separately from the source repository.

```powershell
dotnet restore Laura.sln --locked-mode
dotnet build Laura.sln -c Release --no-restore
dotnet test Laura.sln -c Release --no-restore
Build/Publish.bat
Build/Run.bat
```

Publishing requires a licensed Visual Studio release redistributable folder with the exact CRT hashes in `licenses/vc-runtime-inventory.json`. The default is Visual Studio 2026 Community `VC/Redist/MSVC/14.51.36231/x64`. `Build/Test-Package.ps1` verifies installer extraction, installation/update, packaged dependencies, removal of old integrations and tamper refusal.

Opt-in diagnostics use isolated storage and never capture a physical microphone:

```powershell
# Render native HUD, resource meters, all setup tabs, both languages and fullscreen.
Laura.App/bin/Release/net10.0-windows10.0.19041.0/win-x64/Laura.exe --show --storage _Output/MauiSmoke/Storage --ui-smoke _Output/MauiSmoke

# Real Live API, silent playback; --vad sends synthetic speech followed by silence.
dotnet run --project Build/Smoke/Laura.Smoke.csproj -- _Output/GeminiSmoke --gemini --key-file ../Mark-LV/config/api_keys.json --quick --vad
```

Adding `--live-tools-smoke --import-mark-lv ../Mark-LV/config/api_keys.json` to the isolated UI test explicitly exercises a real Gemini request opening Steam and PCSX2. Do not commit test credentials or private data. Normal launch preserves your protected key and does not import it again.
