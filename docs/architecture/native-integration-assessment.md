# Laura native integration assessment

Assessment date: 2026-10-10. This document records decisions before implementation and is updated as stages are validated.

## Baseline and provenance

- Laura: `eec6621` (clean checkout). C# .NET 9; Windows Forms; App → Platform.Windows → Core. xUnit: 26/26 pass using `dotnet test Laura.sln -p:AnalysisLevel=9.0-recommended`. The installed SDK is 10.0.401; its new default analyzer rules initially fail existing logging expressions. Windows SDK discovery requires execution outside the restricted filesystem sandbox.
- [OpenJarvis](https://github.com/open-jarvis/OpenJarvis): `ecbde4b32091e2a8b02e8acfa41cb5f95e4da560`, Apache-2.0. Python 3.10–3.13 backend, optional Rust extensions, desktop/frontend, engine registries, tool orchestration, SQLite storage/traces, optional learning. Its Windows installer clones the repository, installs uv/Python dependencies and optionally starts a service. This installation pattern is unsuitable for Laura. Its pytest suites are reference material, not Laura validation; no Python runtime is installed in this environment.
- [Mark-LV](https://github.com/FatihMakes/Mark-LV): `c3e795af71bff38bb406c62a2e7a63869cdc8eb2`, copyright 2026 FatihMakes, CC BY-NC 4.0. Python/PyQt6, NumPy, sounddevice, Gemini Live, optional faster-whisper/Vosk/Kokoro, Playwright and OS automation. `setup.py` installs pip dependencies and browsers; no automated test suite was found. It cannot become Laura's installer.
- Distribution intent is not restricted to noncommercial use. Therefore no Mark-LV source, translated implementations, meshes, or assets will be incorporated. General capabilities are independently implemented against platform APIs. Attribution does not override the noncommercial restriction. [Canonical license](https://creativecommons.org/licenses/by-nc/4.0/legalcode).

## Existing application at baseline

Laura already supplies tray lifecycle, Alt+L, red tokens (`Palette.Accent = #D91F2E`), chat, INI settings with atomic writes, JSON localization, Windows natural voice synthesis, optional Sherpa/Kokoro TTS, fixed application launch, volume, lock, weather and browser search. The channel-based assistant executes commands sequentially. Ollama is the only conversation adapter; the catalog reads local Ollama manifests. Conversation history is currently bounded and volatile; no microphone pipeline, model downloader, embedded inference, durable memory, or installer validation exists. Build/Publish.bat points to an obsolete `src/` path. English-only repository guidance is superseded by the explicit request for optional pt-BR.

## Boundaries and dependency decisions

C++ performs inference in the packaged llama.cpp library. C# is retained for mature Core, WinForms, HTTP downloads, SQLite and Windows audio interoperability: replacing them adds native ABI/lifetime complexity without benefit. No Python runtime or reference-project processes will be shipped. Platform adapters enter Core through interfaces and are composed in ServiceConfiguration. Managed cancellation and native disposal must finish before model deletion and application exit. No second event bus or competing agent framework.

## External communications

User-initiated model download: curated Hugging Face HTTPS artifacts and its authenticated CDN redirects, with pinned revision and SHA256. Model weights are never silently installed. Existing explicit weather requests contact wttr.in; web search opens the user's browser. Optional Ollama must remain loopback-only by default. No microphone, screen, personal file, telemetry, model prompt or memory upload is needed for embedded inference. Cloud/remote features remain unavailable until disclosure, consent and credential storage are implemented.

## Validation policy

### Validated stage: bounded desktop tools

Independent implementation of clipboard reads and primary-screen capture with UI-issued Yes/No approval (default No); files are limited to a dedicated `Workspace` folder. Notes and PNGs receive generated names, cannot overwrite files, and permit single-operation undo only if the file is unchanged and not linked. No model argument can grant approval. No external request is made by these tools. `DesktopToolSkill` joins the existing dispatcher; exact whole-command matching avoids activating clipboard/capture from quoted or negated text. Explicit `run steps:` / `executar etapas:` sequences permit at most four registered skill commands, validate all steps before executing, and prohibit recursion or generative fallback. Model-generated plans remain data rather than executable instructions. Tests cover file content/path separation, unsupported executable artifacts, edited-file undo refusal, forged approval arguments and sequence bounds: 55/55 pass; build has zero warnings/errors. Real clipboard/screen capture and approval dialogs have not been exercised against personal desktop content. General file deletion, arbitrary OS control, browser DOM automation, reminders and remote dashboards remain unimplemented; conservative local tools are the maintained alternative.

### Validated stage: local AI foundation

Implemented `LocalModelManager`, reviewed Qwen 2.5 0.5B Q4_K_M download (491,400,032 bytes), Windows CPU/RAM/disk probe, embedded llama.cpp through LLamaSharp/CPU 0.27.0, model setup navigation and first-run display. Settings now load at startup. CPU-only backend avoids a separate server; optional Ollama remains loopback-restricted. Download staging, range resume, size/SHA256/GGUF verification and model deletion are covered by 8 new tests. Build: zero warnings/errors; tests: 34/34. Native generation and UI rendering were subsequently validated; see the delivery report. The catalog intentionally begins with one small reviewed model; installed compatible GGUF files can also be detected. GPU/VRAM detection and additional catalogs are not implemented yet. Core retains platform-independent HTTP/file services consistent with its existing INI/weather services, supplied with injected HTTP dependencies.

### Validated stage: memory

Implemented one SQLite database (`memory.db`) for bounded history (2,000 stored messages, 200 shown) and explicit keyed facts, parameterized literal search, delete, privacy setting, schema version 1, preservation of corrupt/future-schema data and bounded contextual recall. No automatic memory extraction or learning process runs. UI memory operations execute off the UI thread. Tests verify real temporary SQLite restart, SQL injection resistance, selective deletion and future-schema rejection: 38/38 tests pass; full build has zero warnings/errors. The existing dispatcher remains the only orchestrator; advanced model-driven multi-step tools are not yet enabled. History clearing affects saved data; current session remains visible until restart, disclosed in the confirmation.

### Validated stage: multilingual voice and unified UI

English remains default; complete centralized pt-BR catalog, independent UI/conversation cultures, localized command phrases, persisted microphone/output selection and mute (default on). Native Whisper CPU 1.9.1 and reviewed multilingual base weights (147,951,465 bytes, MIT) provide offline English/Portuguese STT, with an optional installed Windows recognizer fallback. Voice model installation is integrated into the Voice page using the same verified/resumable artifact service. Audio remains in memory for a maximum 15-second push-to-talk capture and is discarded after recognition. Recognized text is reviewed before Send; capture starts only while the assistant is idle. This is half-duplex echo prevention, not acoustic echo cancellation or full-duplex interruption. Existing offline WinRT/Sherpa TTS and Laura's state visuals are retained. Text commands now work even with generative mode disabled. Native streamed responses appear in the chat preview. No Mark-LV source/assets were adapted.

Build: zero warnings/errors. Localization parity/format arguments, fallback, independent language settings, device/privacy persistence and Windows reserved path cases tested. Real local inference produced a short streamed answer and unloaded successfully using the GGUF chat template and stateless per-turn native contexts. Real Whisper transcription of a locally synthesized English WAV succeeded in the same process; no microphone recording occurred during testing. Hardware: 12 logical CPUs, 15.9 GiB physical RAM; Windows reports en-US recognizer and en-US/pt-BR TTS voices. Human microphone capture and Portuguese speech accuracy still require validation. Hey Laura, advanced visemes/avatar and cloud voice remain unavailable.

Record real hardware/package tests separately from mocks. Unit tests cover domain and failure boundaries; temporary SQLite/files and fake HTTP exercise integration without downloading gigabytes. A small permissively licensed GGUF may be downloaded into ignored output solely for native smoke validation if feasible. Hardware-dependent speech and clean-machine installation remain unverified until actually exercised. Never declare all phases complete on the strength of mocked responses.

## Current delivery status

The initial table above records the decisions made before code changes. The implemented stages below supersede its planned status entries. Model management/native CPU inference, unified SQLite memory, bounded explicit multi-step tools, push-to-talk/Whisper/Windows TTS, independent English/pt-BR settings and the existing red WinForms interface are implemented. Native inference and synthetic English/Portuguese speech have passed on the development machine. Hardware probes report CPU, physical/available RAM and disk; GPU/VRAM remain unknown. A self-contained Windows x64 folder, ZIP and IExpress installer contain the embedded runtimes and license bundle, with model weights downloaded separately. Release dependency locks and SDK version are committed.

The maintained alternatives are push-to-talk in place of an unvalidated Hey Laura detector, existing Laura state visuals in place of restricted avatar assets, deterministic explicit tools in place of autonomous model-issued OS commands, loopback-only optional Ollama in place of required servers, and explicit memories in place of background learning. Cloud voice, remote pairing/dashboard, unrestricted plugins, general filesystem/window/browser automation and proactive reminders are intentionally absent. Clean-machine testing, human microphone accuracy, false-positive wake detection and GPU acceleration cannot be claimed. See `native-integration-delivery.md` for final evidence and limitations.
